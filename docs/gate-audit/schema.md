# Gate audit schema

## events.jsonl — per-event raw log

One JSON object per line. Append-only under normal operation.

**Single-writer invariant:** `events.jsonl` has concurrent-write safety only for the append path (`gate_event_write` uses a single `printf >>` call, which is atomic for lines under `PIPE_BUF` ≈ 4096 bytes on Linux/macOS). `forge gate-tag` performs a non-atomic read-modify-write (temp-file + mv). Do NOT run `forge gate-tag` concurrently with a hook invocation on the same file. In a single-operator workflow this is satisfied naturally.

**Corruption recovery:** Despite the append-only convention, surgical line repair IS permitted when a line is malformed (e.g. truncated by a process kill). To repair:
1. Identify the bad line: `python3 -c "import json; [json.loads(l) for l in open('docs/gate-audit/events.jsonl')]"` — the failing line number is reported.
2. Remove or fix the line using a text editor.
3. Commit the repaired file with message `chore(gate-audit): repair malformed event line N`.
4. Note the repair in the weekly report's "Notes" section.
Automated recovery is not implemented. "Append-only" means do not silently rewrite history; it does not mean corruption must be preserved.

### Fields

| Field | Type | Description |
|---|---|---|
| `event_id` | string | 16-char hex ID, generated by the hook at fire time. Used by `forge gate-tag <event_id>`. |
| `gate_name` | string | Gate identifier. Current values: `pre-commit-governance`, `layer1-verify`. |
| `timestamp` | string | UTC ISO 8601, e.g. `2026-05-01T09:00:00Z`. |
| `week_iso` | string | ISO 8601 calendar week, e.g. `2026-W18`. Used for grouping in aggregation. |
| `outcome` | string | `"blocked"` — gate fired and blocked the action. `"allowed"` — gate fired and allowed through. |
| `classification` | string or null | Operator post-hoc tag. `null` = unclassified. `"real"` = genuine block. `"false-positive"` = gate was wrong. Set with `forge gate-tag`. |
| `cost_min` | number or null | Operator-estimated time cost in minutes for this event. Optional; contributes to `est_cost_min` in aggregated report. |

### Measurement scope

Events are written by Claude Code hooks only (`pre-commit-governance.sh`, `verify.sh`). Direct
`git commit` calls that bypass Claude Code are not captured. This creates a **known measurement
bias**: frequency counts reflect hook-mediated commits only, not raw git operations. Document
in your analysis if you work with both Claude Code and direct git in the same period.

LLM-critic gates (adversarial-critic, security-reviewer, etc.) are **not instrumented** in
this version. Their events require a different mechanism (agent invocation tracking). This is
deferred to a follow-up issue.

### Bypasses

There is no automated bypass detection. If you explicitly skip a gate (e.g. by operating
outside Claude Code), manually record it by appending a line with `"outcome":"blocked"` and
`"classification":"bypassed"` to `events.jsonl`, then commit the file. Use `"outcome":"blocked"`
(not `"outcome":"bypassed"`) — the aggregator counts bypasses from blocked events that carry
`"classification":"bypassed"`, not from a separate outcome value.

### Rotation

Archive lines older than 90 days to `docs/gate-audit/events.YYYY-Q*.jsonl` when the file
becomes unwieldy. Automated rotation is not implemented; do it manually at end of each quarter.

## aggregate.jsonl — weekly aggregate

One JSON object per (gate_name, week_iso) pair. Overwritten on each weekly run.

| Field | Type | Description |
|---|---|---|
| `gate_name` | string | Same as events.jsonl. |
| `week_iso` | string | ISO calendar week. |
| `frequency` | integer | Total gate fires that week (blocked + allowed). |
| `real_blocks` | integer | Blocked events classified as `"real"`. |
| `bypasses` | integer | Events classified as `"bypassed"`. |
| `false_positives` | integer | Blocked events classified as `"false-positive"`. |
| `est_cost_min` | number or null | Average `cost_min` across tagged events. Null if no cost data. |
| `retention_rec` | string | `KEEP` / `REMOVE` / `INSUFFICIENT_DATA`. See decision rule below. |

### Decision rule

For each gate, examine the last 4 **qualifying** calendar weeks (weeks where `real + fp + bypass > 0`).

```
roi = real / (real + fp + bypass)
```

- If all 4 qualifying weeks have `roi < 0.2` → `REMOVE`
- If fewer than 4 qualifying weeks exist → `INSUFFICIENT_DATA`
- Otherwise → `KEEP`

A `REMOVE` recommendation requires **human approval** before the gate is removed. It is a
signal, not an automatic action. Claude must not modify hook files or open a PR to remove a
gate — even when asked to "act on the recommendation." The operator decides and acts.

## YYYY-WW.md — weekly human-readable report

Generated by `gate-audit-aggregate.sh`. One file per week. Committed to the repo by the
weekly CI cron job or manually via `bash bootstrap/scripts/gate-audit-aggregate.sh`.

Contains one section per gate with a retention badge and a per-week table.
