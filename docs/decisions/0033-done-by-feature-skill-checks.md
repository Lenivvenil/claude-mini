# 0033. Define Done by the checks of the feature skill

* Status: accepted (2026-09-27, PR #342 merged)
* Superseded-by: ~
* Date: 2026-09-27
* Deciders: Lenivvenil (operator); draft by Claude
* Tags: pipeline, review, governance

## Context and Problem Statement

`docs/principles.md` (раздел Definition of Done) и `.github/pull_request_template.md` требуют шагов v1, которых в v2 нет. Это `/review`, `adversarial-critic` внутри него, issue `type:deferred-review`, порог покрытия 80% и проверка `docs-reviewer` и `reliability-reviewer` по путям `bootstrap/`. Раздел о советнике требует два вызова advisor на нетривиальной задаче. Раздел Operational rules ссылается на `/review` и требует еженедельного `/gate-audit`. Разделы ссылаются на runbook-и в `docs/history/`. ADR-0031 разрешил править в принципах только §5–7, поэтому P9 сменил в этих разделах пути, а содержание осталось от v1. В v2 работу от issue до PR ведёт скилл `feature` (`plugin/skills/feature/SKILL.md`, шаги 4–7). Там проверки проекта, сверка с критериями приёмки, критики по затронутым путям и Codex. Двухслойный фильтр ревью ADR-0023 (`verify.sh`, затем LLM-критики) ушёл в `docs/history/` вместе с `/review`.

## Decision Drivers

* Один источник того, что значит «готово». Шаблон PR и принципы не требуют шага, которого нет в скилле, а скилл не делает проверки, которой нет в шаблоне.
* Каждое требование называет отказ, который оно предотвращает. Требование без такого отказа не переносится.
* Автор PR видит в шаблоне то, что он действительно должен приложить.
* Правило о проверках не ссылается на механизм, которого нет.

## Considered Options

* **Option A.** Done определяется шагами 4–7 скилла `feature`. Шаблон PR повторяет состав PR из шага 7. Раздел о триггере ADR остаётся. Раздел о двух вызовах advisor удаляется. ADR-0023 заменяется этим решением.
* **Option B.** Разделы остаются как запись v1 с пометкой в заголовке. Шаблон PR не меняется.
* **Option C.** В принципах пишется отдельный чеклист Done для v2, и скилл `feature` ссылается на него.

## Decision Outcome

Chosen option: **Option A**, because только он даёт один источник (драйвер 1). Опция B оставляет в шаблоне требования к несуществующим шагам, и автор PR либо ставит ложные галочки, либо стирает их руками. Опция C даёт два текста об одном, и они расходятся, как расходились `feature.md` и установщик в ADR-0018. Решение опирается на `docs/principles.md §3`: проверки проекта идут командами проекта, а критики добавляются после них.

Содержание решения.

1. **Definition of Done.** Изменение готово, когда выполнены шаги 4–7 скилла `feature` и их результат приложен к PR, CI зелёный, а PR влил владелец. Раздел принципов называет эти условия и ссылается на скилл. Своего списка он не держит.
2. **Шаблон PR.** Разделы шаблона такие. What & Why с `Closes #N` и ссылкой на ADR, если он был. Таблица критериев приёмки (covered / partial / missing). Проверки проекта с результатом. Итог ревью, то есть какие критики и Codex запускались, что принято, что отклонено и почему. Что осталось владельцу.
3. **Триггер ADR.** Раздел остаётся по содержанию. Ссылка на runbook в `docs/history/` убирается, раздел сам становится источником.
4. **Советник.** Раздел «нетривиальная задача (триггер для advisor × 2)» удаляется. Отказа, который предотвращают два обязательных вызова, в v2 не названо. Advisor остаётся инструментом, который модель вызывает по своему решению.
5. **ADR-0023** получает статус superseded by 0033. Слой 1 в v2 — команды проекта в шаге 4 скилла `feature`, слой 2 — критики и Codex в шаге 6.
6. **Operational rules.** Правило «детерминированный тулинг раньше LLM-проверок» остаётся и ссылается на порядок шагов скилла `feature` (шаг 4 раньше шага 6). Правило о ROI проверок с еженедельным `/gate-audit` заменяется условием входа. Проверка, шаг или пункт промпта добавляются в харнесс, только если названа ошибка, которую они предотвращают. Еженедельного аудита нет.
7. **Скилла `issue` нет.** Запись задачи идёт через `gh issue create` и шаблоны `.github/ISSUE_TEMPLATE/`. Аудит тикетов `audit-pass`, который применял к тикетам двухслойную схему ADR-0023, не переносится.

Уточнение ADR-0031. К разрешённым правкам `docs/principles.md` постоянно добавляются разделы Definition of Done, триггер ADR, триггер advisor и Operational rules. Остальные разделы по-прежнему правятся только через ADR.

### Positive Consequences

* Шаблон PR требует только то, что скилл `feature` делает и прикладывает.
* В принципах больше нет ссылок на runbook-и `docs/history/` как на действующие.

### Negative Consequences

* Без аудита проверка, которая перестала ловить ошибки, остаётся, пока её не заметят на ревью.
* Порог покрытия 80% уходит. Покрытие проверяется, только если его проверяют команды самого проекта.
* PR, собранный без скилла `feature`, заполняет шаблон руками. Честность таблицы приёмки проверяет только владелец при вливании.
* Изменение шагов скилла требует правки шаблона PR в том же PR. Это держится на ревью, теста на совпадение нет. Пропуск всплывёт как пункт шаблона, который скилл не заполняет.

## Pros and Cons of the Options

### Option A

* Good, because источник один, и шаблон совпадает с работой скилла.
* Good, because требования без названного отказа уходят.
* Bad, because порог покрытия пропадает для проектов, где его не задают свои команды.
* Bad, because совпадение шаблона и скилла держится на ревью.

### Option B

* Good, because ничего не меняется, и нового текста для ревью нет.
* Bad, because шаблон требует `/review` и `type:deferred-review`, которых нет.
* Bad, because агент, читающий принципы, получает правила v1 как действующие.

### Option C

* Good, because Done читается в принципах без перехода в скилл.
* Bad, because два текста об одном расходятся при первой правке скилла.

## Confirmation

* После принятия ADR отдельный PR правит `docs/principles.md`, `.github/pull_request_template.md` и ADR-0023 (статус superseded, `Superseded-by: 0033`). После него проверки такие.
  * `grep -nE 'docs/history|/review|/codex-review|deferred-review|adversarial-critic|docs-reviewer|reliability-reviewer|80%|advisor × 2|gate-audit'` ничего не находит в `.github/pull_request_template.md` и в `docs/principles.md` от раздела Definition of Done до конца файла. Выше, в §2, критики названы как действующие агенты v2, и этот раздел решение не трогает.
  * `grep -c '^- \[ \]' .github/pull_request_template.md` печатает 0. Шаблон просит отчёт, а не галочки.
  * В шаблоне есть заголовки разделов из п. 2, по одному на раздел.
* Первый PR, собранный скиллом `feature` после этого, заполняет шаблон без пустых и ложных пунктов.

## Reversibility

Решение снимается новым ADR. Тексты v1 лежат в `docs/history/docs/runbooks/`, их можно вернуть копированием.

## Re-visit Trigger

* Скилл `feature` меняет состав PR, а шаблон остаётся прежним. Тогда нужен тест на совпадение, а не ревью.
* В проекте на харнессе влит PR, где пропущенная проверка нашлась бы по порогу покрытия. Тогда порог возвращается как пункт конфига.
