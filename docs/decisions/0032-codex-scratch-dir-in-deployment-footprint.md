# 0032. Allow the Codex per-run scratch directory in the deployment footprint

* Status: proposed
* Superseded-by: ~
* Date: 2026-09-27
* Deciders: Lenivvenil (operator); draft by Claude
* Tags: installation, security

## Context and Problem Statement

ADR-0031 п. 3 закрывает перечень записей развёртывания вне проекта. Слой машины `setup/harness` проверяет Codex двумя командами: `codex --version` и `codex login status`. Codex 0.157.0 уже на `codex --version` создаёт каталог `~/.codex/tmp/arg0/codex-arg0<случайный суффикс>/` с файлом `.lock`. После прогона приёмки, где слой машины вызвал обе команды, там же остались симлинки `apply_patch`, `applypatch`, `codex-execve-wrapper` на бинарник Codex. Приёмочный тест с голым Claude поэтому падает на пункте «вне `~/.claude` ничего не изменилось». Каталога нет в перечне п. 3, а проверить вход в Codex без настоящего `~/.codex` нельзя.

## Decision Drivers

* Закрытый перечень остаётся закрытым. Каждый путь в нём назван и проверяется тестом.
* Проверка готовности второго мнения. Слой машины сообщает, что Codex установлен и в него выполнен вход, до первой задачи, а не в середине ревью.
* Конфиг и ключи Codex не трогаются. `~/.codex/config.toml` и `~/.codex/auth.json` остаются вне разрешения.
* След не копится. Разрешённая запись не растёт от числа запусков.

## Considered Options

* **Option A.** Дописать в перечень п. 3 один путь `~/.codex/tmp/arg0/`, рабочий каталог самого Codex.
* **Option B.** Не запускать Codex при развёртывании. Вход в Codex становится ручным пунктом `needs-manual` без проверки.
* **Option C.** Общее исключение. Рабочее состояние любой программы, которую проверяет слой машины, не считается записью развёртывания.

## Decision Outcome

Chosen option: **Option A**, because он сохраняет и закрытость перечня, и проверку входа. Каталог принадлежит самому Codex. Три запуска `codex --version` подряд в пустом `$HOME` оставляют один каталог `arg0`, прежний Codex заменяет сам, так что след не растёт. На машине владельца такой каталог уже есть. Option B теряет раннее сообщение о неготовом Codex, и урезанный режим ADR-0031 п. 5 обнаруживается только при первом ревью. Option C открывает перечень для любой будущей программы без названного пути, и тест перестаёт ловить утечку. Решение опирается на `docs/principles.md §5`: граница держится на закрытом перечне, а не на доверии к программам.

Уточнение п. 3 ADR-0031. К перечню добавляется пункт:

* рабочий каталог Codex `~/.codex/tmp/arg0/`, который создают проверки Codex слоя машины, если Codex включён в конфиге.

### Positive Consequences

* Приёмочный тест снова строгий. Вне `~/.claude` он пропускает один названный путь, а любая другая запись, в том числе в `~/.codex`, валит его.
* Слой машины по-прежнему проверяет вход в Codex.

### Negative Consequences

* Нулевого следа вне `~/.claude` снова нет. Каталог `arg0` появляется на машине, где Codex раньше не запускали.
* Разрешение держится на поведении Codex 0.157.0. Если Codex начнёт копить каталоги или писать в другое место, тест упадёт, и понадобится новое решение.
* Тест сверяет путь по префиксу и не проверяет содержимое каталога.

## Pros and Cons of the Options

### Option A

* Good, because перечень остаётся закрытым, путь один и назван.
* Good, because проверка входа в Codex сохраняется.
* Bad, because в `$HOME` появляется запись вне `~/.claude`.
* Bad, because разрешение привязано к поведению одной версии Codex.

### Option B

* Good, because вне `~/.claude` не пишется ничего.
* Bad, because неготовый Codex обнаруживается только при первом ревью.
* Bad, because `codex --version` тоже создаёт каталог, и пропадает даже проверка версии.

### Option C

* Good, because не требует нового ADR на каждую программу.
* Bad, because перечень перестаёт быть закрытым, и тест не отличает рабочее состояние от утечки.
* Bad, because граница снова держится на дисциплине, от которой ушёл ADR-0031.

## Confirmation

* После принятия ADR отдельный PR меняет `tests/acceptance/deploy-bare.sh`: вне `~/.claude` тест пропускает только пути с префиксом `.codex/tmp/arg0/` относительно `$HOME`. Любая другая запись вне `~/.claude`, в том числе `.codex/config.toml` и `.codex/auth.json`, валит пункт (e).

## Reversibility

Решение снимается новым ADR, который убирает пункт из перечня. Тест тогда снова падает на каталоге Codex, пока слой машины его запускает.

## Re-visit Trigger

* После трёх запусков `codex --version` подряд в `~/.codex/tmp/arg0/` больше одного каталога.
* Codex пишет при `--version` или `login status` что-либо вне `~/.codex/tmp/arg0/`.
* Codex получает настройку, которая отключает этот каталог. Тогда пункт убирается из перечня.
